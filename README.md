# immo-eliza-ml

Machine learning model to predict real estate prices in Belgium, built for **Immo Eliza**.

This project covers the full pipeline: data preprocessing, training multiple regression models, evaluating their performance, and generating price predictions for new listings.

## Usage

**Train all 5 models:**
```bash
python src/predict.py
```
This trains Ridge, Decision Tree, Random Forest, SVM and XGBoost (each tuned with its own routine), evaluates them on a held-out test set, and saves the fitted models to `models/price_ensemble.joblib`.

**Predict the price of a new listing:**
```python
from predict import PricePredictorEnsemble

ensemble = PricePredictorEnsemble.load("models/price_ensemble.joblib")

prices = ensemble.predict_price({
    "living_area_m2": 120, "bedrooms": 3, "bathrooms": 1,
    "latitude": 50.83, "longitude": 4.35, "building_year": 1975,
    "property_type": "Apartment", "property_subtype": "apartment",
    "province": "Brussels Capital Region", "region": "Brussels",
    "kitchen_equipped": "Fully equipped", "state_of_the_building": "Normal",
    "epc_score": "C", "nearby_city": "Bruxelles",
    "furnished": 0, "has_garage": 1, "parking_count": 1,
    "has_elevator": 1, "facades": 2, "has_garden": 0,
    "garden_area_m2": 0, "has_terrace": 1, "total_area_m2": 120,
    "km_from_nearby_city": 2.0, "is_nearby_city_prestigious": 0,
    "floor_number": 3,
})
# -> {"ridge": 312450.0, "decision_tree": 298000.0,
```

## Data

The dataset comes from scraped Belgian real estate listings, cleaned and analyzed in an earlier phase of the project. It includes property characteristics (surface area, bedrooms, location, EPC score, building condition, amenities...) and the target variable, `price`.

- **`properties_final.csv`** — raw scraped/cleaned listings, the input fed into `data_preprocessing.py`.
- **`Dataframe_Clean_encoded.csv`** — the fully preprocessed (imputed, encoded, rescaled) output, used directly to train the models in `train.py`.

## Preprocessing

Handled in `data_preprocessing.py`, split into two responsibilities:

- **`DataCleaning`** — handles duplicates, missing values, and drops irrelevant columns/rows.
- **`PreprocessData`** — imputes remaining missing values, encodes categorical features (ordinal encoding for kitchen/state/EPC, one-hot encoding for subtype/province/region, binary encoding for yes/no features), and rescales numeric features.

The same preprocessing steps are reapplied identically when scoring a brand-new listing in `predict.py`, so training and inference always see data in the same format.

## Models

Five regression models are trained and compared:

| Model | Type | Tuning approach |
|---|---|---|
| Ridge | Linear (baseline) | Two-pass grid search on alpha |
| Decision Tree | Non-linear | Two-pass grid search on max_depth |
| Random Forest | Non-linear (ensemble) | n_estimators elbow + random search |
| SVM | Non-linear | Kernel search + random search |
| XGBoost | Non-linear (boosting) | Early stopping + random search |

Each model has its own tuning routine reused as-is from `train.py`; nothing is duplicated in `predict.py`.

**Target transform:** `price` is right-skewed (many affordable properties, a long tail of expensive ones), so every model fits on `log1p(price)` instead of raw price by default (`log_target=True` in `BaseModel`/`PricePredictorEnsemble`). This keeps squared-error-based fitting and tuning from being dominated by a handful of very expensive listings. All predictions and reported metrics (R², RMSE, MAE) are converted back to real EUR automatically, so results stay directly interpretable — pass `log_target=False` to revert to fitting on raw price.

## Results

Final test-set performance after hyperparameter tuning, best to worst — **baseline run, raw price** (`log_target=False`):

| Model | R² | RMSE | MAE |
|---|---|---|---|
| Random Forest | 0.735 | EUR 169,216 | EUR 89,991 |
| XGBoost | 0.711 | EUR 176,915 | EUR 96,168 |
| Ridge | 0.624 | EUR 201,769 | EUR 119,535 |
| SVM | 0.578 | EUR 213,632 | EUR 112,936 |
| Decision Tree | 0.463 | EUR 241,014 | EUR 150,297 |

Random Forest and XGBoost are the two strongest performers, explaining ~71-74% of price variance on unseen listings. Ridge — a plain linear baseline — is a reasonable third, confirming the relationship between features and price is partly linear but benefits from the non-linear models' ability to capture interactions.

## Overfitting

Checked by comparing each model's R² on the training set vs. the held-out test set — a large gap (high train R², much lower test R²) signals the model memorized noise rather than learning general patterns. **Baseline run, raw price** (`log_target=False`):

| Model | Train R² (default) | Test R² (default) | Train R² (tuned) | Test R² (tuned) | Verdict |
|---|---|---|---|---|---|
| Ridge | 0.616 | 0.624 | 0.616 | 0.624 | Good fit, no gap |
| Decision Tree | 1.000 | 0.447 | 0.479 | 0.463 | Fixed by tuning |
| Random Forest | 0.960 | 0.724 | 0.833 | 0.735 | Mild overfitting remains |
| SVM | -0.061 | -0.067 | 0.570 | 0.578 | Fixed by tuning |
| XGBoost | 0.974 | 0.756 | 0.810 | 0.711 | Mild overfitting remains |

Notable findings:
- **Decision Tree** overfit severely by default (perfect train score, weak test score — it had simply memorized the training rows). Capping `max_depth=3` and requiring larger minimum leaf/split sizes brought it to a healthy, generalizing fit.
- **SVM** was actually *underfitting* by default (negative R², essentially no better than predicting the average price). Switching to a `linear` kernel with a properly tuned `C`/`epsilon` fixed this.
- **Random Forest** and **XGBoost** remain the strongest models but still show mild overfitting after tuning (test R² noticeably below train R²) — a good next step would be stronger regularization or more training data if time allowed.

## Feature importance

Each model that supports feature ranking was asked for its top/bottom 5 most influential feature groups (one-hot dummies grouped back to their category, e.g. all `region_*` columns counted as "region"). Rankings were combined across models with a simple points vote (rank 1 = 5 points, ... rank 5 = 1 point):

**Most influential on price:**
1. Living area (m²) — 18 points
2. Bathrooms — 16 points
3. Property subtype — 14 points
4. Province — 11 points
5. Nearby city price/m² — 6 points

**Least influential on price:**
1. Floor number — 13 points
2. Parking count — 9 points
3. Garden area (m²) — 9 points
4. Property type (house/apartment) — 8 points
5. Has terrace — 7 points

This lines up with real-world intuition: size, number of bathrooms, and location (subtype, province) drive Belgian real estate prices far more than secondary amenities like a terrace or a parking spot.
